## 4. Риски

### 4.1. Риски бизнес-анализа

| № | Риск | Вероятность | Последствия | Меры снижения |
|---|---|---|---|---|
| Р-БА-01 | Заказчик не предоставляет доступ к ключевым stakeholders (руководитель ПТО, инженеры) для проведения интервью и наблюдения | Средняя | Задержки извлечения требований, неполнота требований | Заранее зафиксировать расписание в плане проекта; назначить контактное лицо со стороны заказчика; провести пилотное интервью |
| Р-БА-02 | Низкое качество существующего архива документов (плохие сканы, отсутствие метаданных) | Высокая | Недооценка объёма работ по аудиту архива; смещение сроков Этапа 1 | Включить в план резерв 20% времени на аудит; запросить выборку документов заранее для оценки |
| Р-БА-03 | Разногласия между stakeholders по приоритетам функциональных блоков | Средняя | Затягивание согласования требований, неопределённость в бэклоге | Провести Joint Workshop с фиксацией решений; использовать матрицу RACI для распределения ответственности |
| Р-БА-04 | Бизнес-аналитик не имеет достаточной экспертизы в строительной отрасли и терминологии (АОСР, АООК, СПДС и т.д.) | Средняя | Неправильная интерпретация требований, ошибки в user stories | Выделить время на изучение строительной терминологии; привлечь предметного эксперта со стороны заказчика для проверки артефактов |
| Р-БА-05 | Нестабильность требований — постоянные дополнения и изменения в ходе проекта | Высокая | Рост объёма аналитических работ, срыв сроков | Внедрить процесс управления изменениями требований; установить «заморозку» требований перед каждым этапом разработки |
| Р-БА-06 | Ограниченное время участия бизнес-аналитика из-за параллельных проектов | Средняя | Накопление задач, задержки согласований | Зафиксировать загрузку бизнес-аналитика в плане проекта; установить SLA на ответы и согласования |

| Р-СА-04 | Изменение требований к API-контрактам в ходе разработки | Средняя | Переделка спецификаций, рассинхронизация frontend/backend | Использовать contract-first подход; версионирование API; автоматическая генерация документации (OpenAPI/Swagger) |

| Р-СА-06 | Системный аналитик перегружен — одновременно ведёт архитектуру, ТЗ, модели данных, API | Высокая | Снижение качества документации, пропуск деталей | Чёткое распределение приоритетов; поэтапная передача артефактов разработчикам; возможное привлечение помощника |
| Р-СА-07 | Расхождения между спецификацией UI и реальной реализацией frontend | Средняя | Доработки на этапе тестирования, переделки | Раннее вовлечение frontend-разработчика в review спецификаций UI; использование design-system / component library |

### 4.3. Общие риски
