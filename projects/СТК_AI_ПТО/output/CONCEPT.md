# Концепция системы «СТК AI ПТО» — детальное описание

---

## 1. Общие сведения

| Параметр | Значение |
|----------|----------|
| **Полное название** | Корпоративная система искусственного интеллекта «СТК AI ПТО» |
| **Заказчик** | ООО «СТК Инвест» — строительная компания |
| **Целевая аудитория** | Сотрудники производственно-технического отдела (ПТО) |
| **Тип системы** | Веб-приложение с ИИ-ассистентом |
| **Размещение** | On-premise (на серверах заказчика) |
| **Платформа** | Десктоп (веб-интерфейс для ПК) |
| **Одновременные пользователи** | 20–50 человек |
| **Объём архива** | 20 000+ документов, 100+ объектов |
| **Аутентификация** | Active Directory / LDAP |
| **Нормативная база** | СНиП, ГОСТ, СП, СПДС, ГРАСД |
| **Версионность** | Полная (хранение всех версий с историей) |
| **Интеграция с 1С** | Базовый уровень — обмен метаданными |

---

## 2. Цели и задачи системы

### 2.1. Бизнес-цели

- Сокращение времени на подготовку исполнительной документации на **40–60%**
- Снижение количества ошибок и замечаний от заказчиков
- Централизация хранения и быстрого доступа к архиву документации
- Сохранение и систематизация корпоративного опыта
- Снижение зависимости от конкретных сотрудников

### 2.2. Задачи системы

1. Создать единый цифровой архив исполнительной документации по всем объектам
2. Обеспечить интеллектуальный поиск по содержимому документов на естественном языке
3. Автоматизировать генерацию черновиков документов по шаблонам компании
4. Предоставить консультанту-ассистенту для оперативных вопросов ПТО
5. Контролировать комплектность сдаваемой документации
6. Обеспечить безопасность и разграничение прав доступа
7. Подготовить платформу для будущей интеграции с 1С, BIM и корпоративными системами

## 3. Пользователи системы

### 3.1. Роли и права доступа

| Роль | Описание | Основные функции |
|------|----------|------------------|
| **Сотрудник ПТО** | Основной пользователь системы | Загрузка документов, поиск, чат, генерация черновиков, просмотр архива по своим объектам |
| **Инженер ПТО (старший)** | Опытный сотрудник с расширенным доступом | Всё, что у сотрудника + загрузка проектной документации, анализ комплектности |
| **Руководитель ПТО** | Начальник / зам. начальника | Просмотр всех объектов, аналитика, отчёты, согласование документов |
| **Администратор системы** | IT-специалист | Управление пользователями (AD/LDAP), мониторинг, резервное копирование, админ-панель, настройка базы знаний |
| **Системный администратор** | Администратор инфраструктуры | Настройка серверов, Qdrant, OpenAI, резервное копирование, мониторинг производительности |

### 3.2. Сценарии использования по ролям

**Сотрудник ПТО (ежедневный сценарий):**
1. Загружает скан/фото исполнительной документации
2. Система автоматически классифицирует документ и извлекает метаданные
3. Через чат ищет аналогичный документ из архива
4. Генерирует черновик АОСР на основе шаблона и архивных данных

**Инженер ПТО (аналитический сценарий):**
1. Загружает раздел проектной документации (КЖ, КМ)
2. Система формирует перечень требуемой исполнительной документации
3. Сравнивает с фактическим набором документов
4. Выявляет недостающие документы

**Руководитель ПТО (управленческий сценарий):**
1. Просматривает статус комплектности по объектам
2. Анализирует отчёты по загруженным документам
3. Согласовывает сгенерированные документы

**Администратор (административный сценарий):**
1. Добавляет/отключает пользователей через AD/LDAP
2. Мониторит нагрузку и использование API
3. Настраивает резервное копирование
4. Обновляет базу знаний (шаблоны, нормативка)

### 4.2. Слой данных и хранения

| Компонент | Назначение | Технология |
|-----------|-----------|------------|
| **Векторная БД** | Хранение эмбеддингов документов для семантического поиска | Qdrant |
| **Основная БД** | Метаданные документов, пользователи, роли, версионность, журналы действий | PostgreSQL 16+ |
| **Файловое хранилище** | Оригиналы документов (PDF, DOCX, XLSX, DWG, JPEG) | MinIO (S3-совместимое) |
| **Кэш / Сессии** | Кэширование результатов поиска, сессии чата, очереди задач | Redis 7+ |
| **Локальная LLM** | Альтернатива OpenAI API для fully on-premise режима | Qwen / Llama 3 (опционально) |

### 4.3. Слой обработки документов

| Модуль | Функция | Технология |
|--------|---------|-----------|
| **OCR** | Распознавание текста из сканов и изображений | Tesseract 5 + кастомная дообученная ML-модель для строительной терминологии |
| **PDF-модуль** | Извлечение текста, метаданных, структурирование | pdfplumber + PyMuPDF (fitz) |
| **DOCX-модуль** | Извлечение текста и форматирования | python-docx |
| **XLSX-модуль** | Извлечение табличных данных | openpyxl |
| **DWG-модуль** | Полный анализ содержимого чертежей | ODA DWG TrueCore SDK + ML-модель для распознавания элементов |
| **Классификатор** | Автоматическая классификация по типам | Fine-tuned BERT/RoBERTa на корпусе строительных документов |
| **Извлечение метаданных** | Автоматическое определение объекта, заказчика, раздела, вида работ, даты, номера | NLP-модель на базе LLM с prompt-инжинирингом |

## 5. Функциональные блоки

### 5.1. Блок «Цифровой архив»

**Функции:**
- Загрузка документов (PDF, DOCX, XLSX, JPEG, DWG) — drag-and-drop, пакетная загрузка, API
- OCR-распознавание неструктурированных PDF и JPEG
- Автоматическое извлечение метаданных: объект, заказчик, раздел проекта, вид работ, тип документа, дата, номер
- Автоматическая классификация по 11 категориям
- Полная версионность — каждая загрузка создаёт новую версию с сохранением истории
- Привязка документов к объектам строительства
- Предпросмотр документов в браузере
- Поиск по метаданным (фильтры)

**Категории документов:**
1. АОСР (Акты освидетельствования скрытых работ и ответственных конструкций)
2. АООК (Акты испытаний и опрессовок)
3. Общие журналы работ
4. Специальные журналы
5. Исполнительные схемы
6. Реестры исполнительной документации
7. Сертификаты
8. Паспорта
9. Протоколы испытаний
10. Переписка по замечаниям заказчиков
11. Проектная документация

### 5.2. Блок «Семантический поиск (RAG)»

**Функции:**
- Поиск по естественному языку: «Найти аналогичный АОСР», «Документы по армированию плиты»
- Семантическое сопоставление запроса с содержимым документов через эмбеддинги
- Ранжирование результатов по релевантности
- Подсветка найденных фрагментов в исходных документах
- Фильтрация результатов по объекту, типу документа, дате
- Сохранение истории поисковых запросов
- Рекомендация связанных документов

**Технология:**
- Эмбеддинги: OpenAI text-embedding-3-small (или локальная альтернатива)
- Векторный поиск: Qdrant (cosine similarity)
- Реранкинг: Cross-Encoder модель для точной оценки релевантности

### 5.3. Блок «Чат-консультант ПТО»

**Функции:**
- Диалоговый интерфейс с ИИ-ассистентом
- Ответы на вопросы ПТО со ссылками на конкретные документы и нормативные акты
- Поддержка контекста диалога (многореберный диалог)
- Режимы диалога:
  - **Поиск по архиву** — поиск и извлечение информации из документов
  - **Консультант ПТО** — ответы на вопросы по процессам и требованиям
  - **Поиск нормативов** — запросы к базе СНиП, ГОСТ, СП, СПДС, ГРАСД
  - **Анализ проектной документации** — анализ загруженных разделов
- Цитирование источников — каждый ответ содержит ссылки на конкретные фрагменты документов
- Экспорт диалога в PDF/DOCX

### 5.4. Блок «Анализ проектной документации»

**Функции:**
- Загрузка разделов проектной документации (КЖ, КМ, ВК, ЭО, ОВиК и др.)
- Автоматическое определение разделов и их содержимого
- Формирование перечня необходимой исполнительной документации по каждому разделу
- Контроль комплектности — сравнение требуемого и фактического набора
- Визуализация прогресса комплектности по объектам и разделам
- Уведомления о недостающих документах

### 5.5. Блок «Генерация документов»

**Функции:**
- Генерация черновиков на основе шаблонов СТК Инвест:
  - АОСР
  - АООК
  - Журналы работ (общие и специальные)
  - Реестры исполнительной документации
  - Сопроводительные письма
  - Ответы на замечания заказчиков
- Использование данных из:
  - Шаблонов компании (DOCX-шаблоны с полями)
  - Архивных документов (похожие ранее заполненные формы)
  - Проектной документации
  - Нормативной базы
- Предпросмотр и редактирование сгенерированного документа
- Экспорт в DOCX/PDF
- Версионность сгенерированных документов

### 5.6. Блок «База знаний»

**Содержание:**
- Архив исполнительной документации (все загруженные документы)
- Корпоративные шаблоны документов
- Нормативная база: СНиП, ГОСТ, СП, СПДС, ГРАСД
- Проектная документация
- Накопленный опыт компании (ответы на типовые вопросы, лучшие практики)

**Функции:**
- Управление базой знаний (админ-панель)
- Добавление/редактирование шаблонов
- Обновление нормативной базы
- Категоризация и тегирование материалов
- Поиск по базе знаний

### 5.7. Блок «Администрирование и мониторинг»

**Функции:**
- Управление пользователями (синхронизация с Active Directory / LDAP)
- Ролевая модель разграничения прав
- Мониторинг состояния системы (загрузка CPU/RAM, дисковое пространство, состояние сервисов)
- Мониторинг использования OpenAI API (затраты, количество токенов)
- Настройка резервного копирования (базы данных, файлы, векторные индексы)
- Журналирование действий пользователей (audit log)
- Управление квотами и лимитами
- Отчёты по активности пользователей

### 5.8. Блок «Аналитика и отчёты»

**Функции:**
- Статистика загруженных документов по объектам и типам
- Прогресс комплектности по объектам
- Активность пользователей
- Затраты на OpenAI API
- Топ-запросов в чате и поиске
- Экспорт отчётов в PDF/Excel

### 5.9. Блок «Интеграция с 1С»

**Уровень: базовый (обмен метаданными)**

**Функции:**
- Выгрузка метаданных объектов из 1С (наименование, адрес, статус)
- Загрузка в 1С номеров и статусов сгенерированных документов
- Обмен через файловый формат (XML/JSON) или HTTP API
- Настройка расписания синхронизации

## 6. Нормативная база

Система должна содержать структурированную базу следующих нормативных документов:

| Категория | Содержание |
|-----------|-----------|
| **СНиП** | Строительные нормы и правила (все актуальные редакции) |
| **ГОСТ** | Государственные стандарты (строительные, технические) |
| **СП** | Своды правил |
| **СПДС** | Система проектной документации для строительства |
| **ГРАСД** | Группа требований к графическому оформлению |
| **Технические регламенты** | ФЗ-384, ФЗ-123 и др. |
| **СанПиН** | Санитарные нормы и правила |

Каждый документ должен быть разбит на разделы/пункты для точного цитирования в ответах чата.

## 7. DWG-модуль (полный анализ содержимого)

### 7.1. Загрузка и хранение
- Приём DWG-файлов различных версий (AutoCAD 2010–2026)
- Хранение оригиналов в файловом хранилище

### 7.2. Извлечение метаданных
- Чтение свойств DWG (автор, дата создания, масштаб, пространство листа)
- Извлечение таблиц спецификаций
- Извлечение надписей и текстовых блоков
- Извлечение размеров

## 12. Риски и меры их снижения

| Риск | Вероятность | Последствия | Меры снижения |
|------|-------------|-------------|---------------|
| Низкое качество OCR на старых сканах | Средняя | Неполное извлечение текста | Дообучение ML-модели на корпусе документов СТК Инвест + ручная верификация |
| Ошибки классификации документов | Средняя | Неверная организация архива | Комбинированный подход: ML-классификатор + ручная корректировка + дообучение |
| Высокая стоимость OpenAI API | Средняя | Превышение бюджета | Опциональный переход на локальную LLM; оптимизация промптов |
| Сложность DWG-анализа | Высокая | Неполный анализ чертежей | Итеративная разработка; фокус на наиболее частых типах чертежей |
| Низкая адаптация сотрудников | Средняя | Недоиспользование системы | Раннее вовлечение пользователей; поэтапное обучение; поддержка |
| Производительность при 20-50 пользователях | Низкая | Медленная работа | Масштабируемая архитектура; кэширование; оптимизация запросов |
