## 1. Границы оценки (Scope)

Оценивается объём работ аналитика на разработку ТЗ и эскизного/технического проекта
для **Фазы 1 (MVP)**: раздел «Услуги» в существующем приложении, категория «Уход за
садом», фронт клиента + фронт мастера (авторизованный) + минимальная admin-панель
с ручным распределением заявок, оплата физлиц, выплаты мастерам-самозанятым.

| Этап каталога | Причина исключения |
|---|---|

## 6. Допущения

1. Количество экранов (25), ролей (3), бизнес-процессов (2), Use Case (8), User
   Story (20), сущностей (7) и функциональных требований (15) — реконструированы
   из концепции v1 на уровне пресейла, не из детальной спецификации. После этапа
   1.2/1.3 (реальный сбор и анализ требований) цифры почти наверняка изменятся.
2. Уровень сложности по большинству пунктов принят «средний» по умолчанию — не
   подтверждён заказчиком.
3. Интеграция с сервисом выплат самозанятым/ФНС оценена как «сложная» (3 уровень)
   исходя из отсутствия открытого API у типичных сервисов такого рода — требует
   подтверждения после выбора конкретного провайдера.
4. Этапы 0.3–0.5 (анализ существующей системы ЛеманаПРО) не включены из-за
   отсутствия доступа к текущему стеку — при получении доступа оценка должна быть
   дополнена (см. риск RK-005 в `projects/lemana_pro/output/reports/6_3_risk_assessment_lemana_pro_20260730_120303.md`).
5. 2.5 (бизнес-ограничения) и 2.7 (критерии приёмки) — нормочасы в источнике не
   заданы, оценены экспертно (4 ч и 8 ч соответственно), это грубые ориентиры.
6. 5.1 (формальная документация) и 6.1 (обучение персонала) исключены по
   умолчанию — не запрошены в концепции для MVP.
