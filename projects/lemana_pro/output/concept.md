# Концепция проекta: Платформа услуг «ЛеманаПРО. Услуги»

**Заказчик:** ЛеманаПРО (сеть гипермаркетов и интернет-магазин товаров для дома, ремонта и стройки)
**Исполнитель:** АО «СимбирСофт» (заказная разработка, аутстафф, 1500+ специалистов, 25 лет на рынке)
**Дата:** 2026-07-30
**Версия:** v1 (черновик для согласования, требует уточнений — см. раздел 10)

---

## 1. Executive Summary

ЛеманаПРО располагает розничной сетью и интернет-магазином (мобильное приложение + веб-сайт) для B2C- и B2B-клиентов. Проект расширяет существующую цифровую платформу новым направлением — **маркетплейсом бытовых услуг**: уход за садом, аренда оборудования, ремонт и строительство. Модель распределения заявок между исполнителями аналогична агрегаторам такси (Яндекс Такси): заявка автоматически находит ближайшего доступного сертифицированного мастера.

Проект реализуется поэтапно. **MVP (Фаза 1)** ограничен одной категорией услуг — «Уход за садом» — и минимальным набором ролей (клиент, мастер, admin с ручным распределением), чтобы проверить бизнес-модель до масштабирования на «Аренду оборудования» и «Ремонт и стройку».

---

## 2. Бизнес-контекст и цель проекта

- У ЛеманаПРО уже есть аудитория интернет-магазина (физ- и юрлица), готовая инфраструктура заказов и оплаты.
- Идея — монетизировать эту аудиторию через **услуги**, смежные с ассортиментом магазина (товары для сада/ремонта → услуги по саду/ремонту).
- Целевая бизнес-модель: **комиссия платформы с каждого заказа**; исполнители («мастера») — юридически самозанятые или ИП, работающие как сертифицированные партнёры ЛеманаПРО, не штатные сотрудники.
- Ценность для ЛеманаПРО: новый источник выручки (комиссия), рост LTV клиента, укрепление позиционирования «от покупки материалов — до готового результата».

---

## 3. Границы и фазы проекта (Scope & Roadmap)

Проект разбит на 3 фазы. Полная целевая архитектура и полный перечень экранов (разделы 6–7) описывают **конечное состояние**; в скобках у каждого элемента указана фаза, к которой он относится.

| Фаза | Содержание | Ориентировочная цель |
|---|---|---|
| **Фаза 1 — MVP** | Раздел «Услуги» в мобильном приложении. Категория **«Уход за садом»** целиком (Уборка участка, Ландшафтные работы, Озеленение). Фронт клиента, фронт мастера (базовый), admin-панель с **ручным** распределением заявок. Оплата физлиц. | Проверить спрос и юнит-экономику на одной категории |
| **Фаза 2** | Автоматическое распределение заявок (dispatch engine). Категория **«Аренда оборудования»**. Публичный лендинг «стать сертифицированным мастером». Оплата юрлиц + интеграция с 1С. | Масштабирование операционки, выход на B2B |
| **Фаза 3** | Категория **«Ремонт и стройка»**. Веб-версия раздела на сайте. Полная admin-панель (финансы, отчётность). Рейтинги и геймификация мастеров. | Полное покрытие всех услуг, зрелая платформа |

## 5. Сквозной пользовательский сценарий (пример, Фаза 1)

1. Клиент в мобильном приложении ЛеманаПРО открывает новый раздел **«Услуги»**.
2. Видит 3 карточки категорий: *Уход за садом*, *Аренда оборудования*, *Ремонт и стройка* (в MVP кликабельна только первая).
3. Выбирает **«Уход за садом»** → экран «Перечень услуг»: *Уборка участка*, *Ландшафтные работы*, *Озеленение*.
4. Выбирает **«Уборка участка»** → экран с чек-листом работ (скашивание травы, спил деревьев, вывоз мусора, корчевание пней, выравнивание земли) — клиент отмечает нужные пункты.
5. Внизу экрана — динамически пересчитываемая **итоговая стоимость за час работ**.
6. Клиент указывает адрес объекта, дату/время, способ оплаты → подтверждает заказ.
7. Заказ уходит в Dispatch (в MVP — попадает в очередь admin-панели на ручное назначение; в Фазе 2 — автораспределение по геолокации/доступности).
8. Назначенный мастер получает заказ в своём приложении, принимает/отклоняет.
9. Мастер выполняет работы, отмечает чек-лист, прикладывает фото результата.
10. Клиент подтверждает выполнение, оплачивает (если не была предоплата), оставляет оценку.

### 6.2 Ключевые архитектурные решения

| Область | Решение | Комментарий |
|---|---|---|
| Встраивание в существующее приложение | Раздел «Услуги» — отдельный модуль/мини-приложение, подключаемый через навигацию существующего аппа | Минимизирует риск для стабильности e-commerce функциональности |
| Backend | Выделенный сервисный контур (микросервисы или модульный монолит) для услуг, отдельно от core e-commerce backend | Разная доменная логика, разная скорость изменений (MVP-темп) |
| Dispatch Engine | Аналог логики Яндекс Такси: подбор мастера по геолокации, доступности, рейтингу, очередь заявок при отсутствии свободных мастеров | В MVP заменяется ручным распределением через admin |
| Оплата физлиц | Существующий эквайринг платформы ЛеманаПРО (если есть) либо отдельный платёжный провайдер | Требует уточнения (см. вопросы) |
| Оплата мастерам | Выплаты самозанятым/ИП с удержанием комиссии платформы; для самозанятых — формирование чека (интеграция с ФНС «Мой налог» или аналог) | Юридическое требование 422-ФЗ |
| Интеграция с 1С | Учёт заказов, бухгалтерия, оплата юрлиц по счёту | Фаза 2 |
| Авторизация мастеров | Отдельный контур логина (телефон + верификация статуса сертификации), не путать с клиентской авторизацией | — |

### 6.3 Нефункциональные требования (черновой список)

- **152-ФЗ** — защита персональных данных клиентов и мастеров (паспортные данные, адреса).
- **422-ФЗ** — корректное оформление выплат самозанятым (чек, налоговый агент/партнёр по выплатам).
- **Сезонность нагрузки** — пик спроса на «Уход за садом» весна/лето, требуется расчёт на пиковую нагрузку.
- **SLA распределения заявки** — целевое время от создания заказа до назначения мастера (нужно определить целевой показатель).
- **Гео-точность** — корректный адрес объекта (участка/дома), не всегда совпадающий с адресом доставки товаров.

## 8. Монетизация

- **Модель:** комиссия платформы с каждого выполненного заказа (% удерживается при выплате мастеру).
- **Юридический статус мастеров:** самозанятые / ИП — внешние сертифицированные партнёры, не штатные сотрудники ЛеманаПРО.
- **Следствия для архитектуры:** необходим модуль формирования чеков для самозанятых (интеграция с сервисом типа «Мой налог» или аналогичным партнёром по выплатам), раздельный учёт комиссии платформы и суммы, причитающейся мастеру.
- Открытый вопрос: размер комиссии, наличие мин. чека/платы за подписку — не определено, требует решения на стороне ЛеманаПРО (маркетинг/финансы).

## 9. Риски

| Риск | Влияние | Комментарий |
|---|---|---|
| Сезонность спроса (сад, стройка) | Высокое | Неравномерная загрузка мастеров и выручки в течение года |
