# Правила RE_Project

## 1. Создание нового проекта

При создании нового проекта создается папка с названием проекта в папке `projects`.

Каждый проект относится к одной из трёх компетенций `ainalyst` — определи
компетенцию по формулировке запроса **до** создания папки, это решает, какой
скилл стартует внутри проекта. Полное описание компетенций — `README_RE.md`
в корне эпика.

**1.1. Триггеры и компетенции:**

| Компетенция | Когда | Триггеры | Что стартует после создания папки |
|---|---|---|---|
| 1. Оценка аналитики (до контракта) | Нужно оценить трудозатраты/сроки на аналитику — контракт на разработку ещё не заключён | «создай оценку», «создай оценку нового проекта», «оцени проект», «оцени продуктовый проект», «оцени discovery/предпроект», «посчитай нормочасы», «сколько часов на аналитику» | `ainalyst/skills/analyst_estimate/SKILL.md` — **не** переключай на Главу 3 и не запускай `planning_prep` |
| 2. Аналитика по BABOK v3 (проект идёт) | Контракт заключён, команда разработки собрана, работа над требованиями уже начинается | «создай новый проект», «начинаем проект», «стартуем аналитику по проекту», «создай новую концепцию» | `ainalyst/skills/planning_prep/SKILL.md` (Глава 3) — по обычной логике `ainalyst/CLAUDE.md` |
| 3. Прочие задачи | Не ИТ-проект: управление, направление аналитики, операционные задачи | «создай папку нового проекта», «создай подпроект» + описание задачи не по BABOK | конкретный скилл/MCP по содержанию запроса, без привязки к главам BABOK |

**Правило разграничения Компетенций 1 и 2:** если в запросе есть слова про
оценку/трудозатраты/нормочасы/часы («оцени», «оценка», «нормочасы», «сколько
часов») — это **всегда Компетенция 1**, даже если рядом встречается фраза
«новый проект». Правило Компетенции 1 приоритетнее — не начинай с
`planning_prep`, даже если по инерции кажется, что это старт проекта по Главе 3.

**1.2.** Название нового проекта по умолчанию `new_номер`, если не задано
конкретное название. Для Компетенции 1 (оценка) можно использовать префикс
`estimate_<имя>`, если это помогает не спутать проект-оценку с проектом полной
аналитики по тому же клиенту.

**1.3.** Автоматически переходить в созданный проект командой `cd`.

## 2. Структура проекта

В созданной папке проекта автоматически создаются 2 папки: `input` и `output`.

## 3. Данные проекта

**3.1.** Все входящие данные сохранять в `input` и считать контекстом проекта.

**3.1.1. Триггеры:** входные данные, информация от клиента, запись созвона, сохрани документы клиента.

**3.2.** Все созданные результаты сохранять в папке `output`.

**3.2.1. Триггеры:** создай концепцию, создай оценку, создай план работ, создай требования, создание описание системы, создай описание архитектуры, создай перечень фич, создай User Story, создай Use Case.

**3.2.2.** При обновлении или внесении изменний в концепцию запрашивать: "Обновить сущесвующую или создать новый документ?". При ответе пользователя создать, создать новый или новый, создать в папку открытого проекта новый файл со следующим порядковым номером, например, concept_v2.md 

## 4. Изоляция контекстов

Контексты разных проектов используются отдельно и не смешиваются.

## 5. Инструментарий

Проект `aianalyst` со всеми скиллами и зависимостями используется для всех проектов папки `projects`.

## 6. Переключение проектов

Меняй проект по триггерам: переключи на проект, смени проект, открой проект/концепцию/подпроект.

## 7. Инструмент OpenSpec

OpenSpec (создание документации и декомпозиция на задачи для агентской
разработки) используется в конкретном проекте **только при дополнительном
подтверждении пользователя**. По умолчанию во всех проектах эпика работает
`ainalyst`, а не OpenSpec — не запускай и не предлагай OpenSpec как шаг по
умолчанию, даже если задача похожа на спецификацию/декомпозицию.
