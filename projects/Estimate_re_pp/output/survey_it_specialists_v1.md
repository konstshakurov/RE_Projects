# Опрос: артефакты аналитики на продуктовых проектах — потребности ИТ-специалистов

**Цель опроса:** определить, какие артефакты аналитика (СА/БА) и с какой
минимальной детализацией реально нужны команде на продуктовом проекте, чтобы
не тратить трудозатраты на артефакты/детализацию, которые никто не использует.

**Аудитория:** ИТ-специалисты СимбирСофт, участвовавшие в продуктовых проектах
(разработчики, архитекторы, DevOps, управленцы — PM/TL/presale) — то есть
потребители результатов работы аналитика, а не сами аналитики.

**Формат:** анонимный, ~10–15 минут. Результаты используются для методологии
оценки трудозатрат аналитики на продуктовых проектах (не для оценки
конкретных людей/проектов).

## Блок 2 — Артефакты: нужность и минимальная детализация

По каждому артефакту — два вопроса. Шкала детализации одинакова для всех строк:

- **Не нужен** — можно обойтись без документа, информация передаётся устно/в коде
- **Краткая** — 1 стр., ключевые тезисы без таблиц полей и примеров
- **Средняя** — структурированный документ с таблицами (поля/статусы/роли), без детальных edge-cases
- **Подробная** — с примерами (JSON/код/скриншоты), альтернативными сценариями, edge-cases — как в эталонных шаблонах СимбирСофт

Для каждого артефакта отметьте: (а) насколько он нужен вам в работе, (б) какая
детализация минимально достаточна, чтобы вы могли эффективно работать без
дополнительных уточнений у аналитика.

## Технические заметки к опросу

- Вопрос 3 (опыт продуктовых проектов) используется как фильтр валидности —
  ответы респондентов без опыта продуктовых проектов не учитываются в
  агрегации по Блоку 2, но их можно посмотреть отдельно для сравнения ожиданий
  vs. реальной потребности.
- Результаты по Блоку 2 стоит агрегировать в разрезе роли (Блок 1, вопрос 1) —
  ожидаемо разработчики и управленцы дадут разные ответы по одному и тому же
  артефакту (например, НФТ важнее для DevOps/архитектора, чем для frontend;
  ТЗ и конкурентный анализ важнее для управленцев, чем для разработчиков).
- Список артефактов в Блоке 2 составлен по итогам изучения шаблонов
  `input/templates_full/` и `input/templates_pp/`, см. `output/artifact_inventory.md`.
  Чек-лист ревью ТЗ (Вигерс) не включён — это процессный инструмент качества,
  не документ-артефакт, потребляемый ИТ-командой.
