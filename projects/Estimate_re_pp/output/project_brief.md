# Estimate_re_pp — Методология оценки аналитики на продуктовых проектах

**project_id:** `estimate_re_pp`
**Дата создания:** 2026-08-10
**Статус:** инициация

---

## 1. Контекст компании — АО «СимбирСофт»

- Направление Аналитики: **100 специалистов** (СА/БА).
- Специалисты в основном подключаются **в команды проектов крупных заказчиков**:
  финтех, банки, ритейл, e-commerce, промышленность и др.
- В ролях преобладают обязанности **системного аналитика (СА)**, но все владеют
  и бизнес-аналитикой (БА).
- Заказчик документа — руководитель направления Аналитики.

## 2. Цель проекта

Разработать методологию для **минимально необходимой и достаточной** оценки
этапа аналитики на **продуктовом проекте** (в отличие от существующей методики
для больших полноценных проектов и Discovery-фазы). Методология должна включать:

1. Состав этапов, артефактов и структуру оценки аналитики на новом продуктовом проекте.
2. Степень детализации артефактов.
3. Уровень сложности артефакта.
4. Трудозатраты на артефакты (нормочасы).

## 3. Ограничения

**Главное ограничение — сроки и стоимость этапа аналитики должны быть
конкурентоспособными** при выборе между КП СимбирСофт и КП конкурентов
на продуктовые проекты. Методология должна давать компактную, а не
максимально подробную оценку (в отличие от `normo_hours_catalog.md`).

## 5. Выходные данные (результаты проекта)

1. Документ с новыми нормочасами для продуктовых проектов.
2. Критерии и условия, определяющие: какие артефакты включать/исключать,
   какой уровень детализации и сложности применять.
3. Опрос для ИТ-специалистов СимбирСофт (потребителей результатов аналитики) —
   какие артефакты и в какой детализации ожидаются от аналитика на продуктовом
   проекте; опрос включает валидацию респондента (грейд, роль/должность, опыт
   продуктовых проектов).
4. Прочие вспомогательные документы по ходу проекта.
5. Обновление скилла `ainalyst/skills/analyst_estimate/SKILL.md` и новый референс
   `references/normo_hours_pp.md`.

   пользователя** для конкретной задачи (по умолчанию работает ainalyst).

## 6. Ключевые бизнес-критерии оценки (запрашиваются у пользователя при каждой новой оценке продуктового проекта)

- Есть ли максимальный срок/бюджет этапа аналитики?
- Документация будет вестись AI-агентом или живым аналитиком?
- (дополняется по ходу разработки методологии)

## 7. Процесс работы над проектом

Роль ассистента — эксперт по разработке продуктовых проектов:
1. Принимает цель, ведёт диалог, уточняет детали, двигается по шагам плана.
2. Сохраняет и накапливает контекст внутри проекта (этот документ обновляется
   по ходу работы).
3. Связывает цель с ограничениями (сроки/стоимость vs. полнота методологии).
4. Корректирует план при необходимости — по согласованию с пользователем.
