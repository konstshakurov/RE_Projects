# RE_Projects — общий эпик-проект

Это корень общего локального эпик-проекта. Здесь ведутся разные проекты
(системная и бизнес-аналитика, концепции ИТ-проектов, интерактивные веб-прототипы
и другие) в папке `projects/`. Общий инструментарий для всех них — `ainalyst/`
(BABOK v3 skills + MCP-серверы, см. ниже).

## Компетенции AInalyst в этом эпике

`ainalyst/` используется в эпике для нескольких разных по смыслу видов
работы — не путай их между собой при выборе скилла:

1. **Оценка этапа аналитики ИТ-проекта** (контракт на разработку ещё не
   заключён, разработка не началась) — три вида: продуктовый проект (минимум
   артефактов), полная аналитика (максимальная детализация), Discovery/пресейл
   (уровень ТЗ). Скилл: `ainalyst/skills/analyst_estimate/SKILL.md`.
2. **Аналитика по методике BABOK v3** (контракт заключён, команда разработки
   собрана, работа над проектом уже идёт) — главы 3–7 `ainalyst`, начиная с
   `skills/planning_prep/SKILL.md`.
2.1. **Предпроект** (контракт заключён только на сам предпроектный этап, до
   контракта на полную разработку; команда — фулстек-аналитик + архитектор +
   PM, ~2-3 недели) — техническая «Концепция проекта», отвечает на вопрос
   «КАК разрабатывать» (в отличие от лёгкой Концепции на присейле внутри
   Компетенции 1 — вопрос «ЧТО делать»). Скилл:
   `ainalyst/skills/analyst_pre_project/SKILL.md`.
3. **Прочие задачи** — не ИТ-проект: управление, направление аналитики,
   операционные задачи; конкретные скиллы/MCP выбираются по содержанию запроса.

Триггеры для создания проекта каждой компетенции и правило их разграничения
(чтобы запрос на оценку не запускал Главу 3, а запрос на предпроект не
путался ни с оценкой, ни с полной разработкой) — `projects/Rules/Rules.md`,
раздел 1. Полное описание возможностей и структуры эпика — `README_RE.md`
в корне.

### Важно: пересчёт путей из ainalyst/CLAUDE.md

Сессия Claude Code запущена из корня эпика (`RE_Projects/`), а не из `ainalyst/`.
Все относительные пути, упомянутые в инструкции AInalyst выше, отсчитывай от
папки `ainalyst/`:

| В инструкции AInalyst | Реальный путь из корня эпика |
|---|---|
| `skills/<...>/SKILL.md` | `ainalyst/skills/<...>/SKILL.md` |
| `docs/user-guide/...` | `ainalyst/docs/user-guide/...` |
| `phase.py` | `ainalyst/phase.py` (запускать `python ainalyst/phase.py`) |
| `inputs/` (папка AInalyst) | не используется в эпике — см. ниже |

### Входные и выходные данные конкретного проекта

Для входных/исходных материалов и результатов конкретного проекта из `projects/`
действуют правила `Rules.md` (см. выше), а не папка `ainalyst/inputs/`:
- входные материалы клиента/проекта → `projects/<project_id>/input/`
- готовые документы БА (концепции, оценки, планы, требования и т.д., создаваемые
  напрямую Claude Code без MCP) → `projects/<project_id>/output/`

### Артефакты BABOK-инструментов AInalyst (JSON/MD, ведутся через MCP)

MCP-серверы AInalyst (Компетенция 2, главы 5–7) сохраняют свои артефакты (граф
трассировки, приоритизация, отчёты 7.1–7.6 и т.д.) относительно рабочей
директории Claude Code, то есть **в корне эпика**, внутри самого проекта —
не в отдельном общем каталоге платформы:
- `projects/<project_id>/output/data/` — JSON для MCP
- `projects/<project_id>/output/reports/` — Markdown-отчёты для BA
- `projects/<project_id>/output/specs/` — спеки 7.1 и другие артефакты системного анализа

`project_id` — то же имя, что и папка проекта в `projects/` (например, для
`projects/lemana_pro` → `project_id = lemana_pro`), поэтому артефакты MCP и
рабочие материалы проекта всегда лежат в одной и той же папке `projects/lemana_pro/`.

### MCP-серверы

Список MCP-серверов зафиксирован в `.mcp.json` в корне эпика (полный набор —
`full`, все 22 сервера + Confluence, скопирован из `ainalyst/.mcp.json`).
Эпик объединяет разные проекты и задачи одновременно, поэтому здесь не
переключаются фазы BABOK (`python phase.py <фаза>`) — это оптимизация под
одиночный проект с ограниченным контекстным окном. Если нужно экономить
контекст для одного длинного проекта, открой Claude Code прямо в `ainalyst/`
и переключай фазы там.

При первом запуске Claude Code в этой папке подтверди подключение
MCP-серверов из `.mcp.json`, когда появится запрос на approval.
