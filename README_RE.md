# RE_Projects

Локальный эпик-проект: единая кодовая база, в которой ведутся разные проекты
системной и бизнес-аналитики — концепции ИТ-проектов, оценки трудозатрат,
интерактивные веб-прототипы и другие рабочие задачи аналитика. Общий
инструментарий для всех проектов эпика — платформа **AInalyst** (`ainalyst/`):
скиллы и MCP-серверы по методологии BABOK v3 плюс компания-специфичные
методики (например, оценка трудозатрат по нормочасам СимбирСофт).

---

## Возможности

AInalyst внутри эпика используется по трём компетенциям — они не смешиваются
между собой, и для каждой запускается свой набор скиллов.

### Компетенция 1 — Оценка этапа аналитики ИТ-проекта

До заключения контракта на разработку, до старта самого проекта. Три вида
оценки (скилл `analyst_estimate` сам уточняет нужный вид):

- **Продуктовый проект (ПП)** — минимальный набор артефактов и минимально
  необходимая детализация, приоритет на конкурентоспособность КП по срокам и
  стоимости.
- **Полная аналитика** — максимально детальная оценка на полноценную
  разработку ТЗ и далее, для крупного/долгого проекта.
- **Discovery/пресейл** — предпроектная фаза: детальная концепция проекта
  уровня ТЗ с минимальной системной аналитикой, чтобы затем вся команда
  разработки дала точную оценку сроков и трудозатрат.

### Компетенция 2 — Аналитика по методике BABOK v3

Контракт заключён, команда разработки собрана, разработка уже началась.
Полный цикл BABOK: планирование (Гл. 3), выявление требований (Гл. 4),
управление жизненным циклом требований (Гл. 5), стратегический анализ (Гл. 6),
проектирование требований (Гл. 7) — 21 скилл и MCP-инструменты AInalyst,
которые пополняются по мере развития платформы.

Компетенция объединяет роли **бизнес-аналитика (БА) и системного аналитика
(СА)** — аналитик эпика работает как фуллстек-аналитик, а не только как БА.
Помимо 21 скилла BABOK v3 (методология и процесс: выявление, трассировка,
приоритизация, стратегический анализ, спецификация требований) компетенция
включает специализированные скиллы системного анализа для конкретных
технических артефактов — проектирование БД, постановка задач на REST API-методы,
UML Sequence-диаграммы — из раздела «Дополнительные скиллы» в
`ainalyst/CLAUDE.md`. Эти скиллы не требуют переключения фазы и по смыслу
ближе всего к фазе `design` (Глава 7), но применимы в любой активной фазе.

### Компетенция 3 — Прочие задачи

Всё, что не является ИТ-проектом в узком смысле: управленческие задачи,
задачи направления аналитики, операционные задачи. Здесь применяются
отдельные скиллы и MCP-инструменты AInalyst по содержанию конкретного запроса.

Разграничение триггеров между Компетенцией 1 и Компетенцией 2 (чтобы запрос
на оценку не запускал по ошибке Главу 3 BABOK) — в `projects/Rules/Rules.md`,
раздел 1.

## Структура проекта

```
RE_Projects/
├── CLAUDE.md                    ← точка входа для Claude Code в эпике
├── README_RE.md                 ← этот файл
├── .mcp.json                    ← MCP-серверы эпика (полный набор — "full")
│
├── ainalyst/                    ← платформа AInalyst (общий инструментарий)
│   ├── CLAUDE.md                ← роль, фазы, скиллы, MCP
│   ├── README.md                ← установка и работа с AInalyst отдельно
│   ├── phase.py                 ← переключатель фаз BABOK (не используется в эпике)
│   ├── skills/
│   │   ├── planning_prep/ ...   ← скиллы глав 3–7 BABOK v3 (Компетенция 2)
│   │   └── analyst_estimate/    ← оценка трудозатрат (Компетенция 1)
│   └── docs/                    ← пользовательская и техническая документация
│
└── projects/                    ← рабочие проекты эпика
    ├── Rules/
    │   └── Rules.md             ← правила создания/структуры проектов, триггеры
    └── <project_id>/
        ├── input/                ← входные материалы клиента/проекта
        └── output/               ← результаты проекта
            ├── concept.md, estimate.md, ...  ← документы БА (Компетенции 1/3)
            ├── data/              ← JSON — машиночитаемые данные MCP-инструментов AInalyst (Компетенция 2)
            ├── reports/           ← Markdown-отчёты MCP-инструментов AInalyst (Компетенция 2)
            └── specs/             ← спеки 7.1 и другие артефакты системного анализа
```

Артефакты MCP-инструментов AInalyst (граф требований, приоритизация, отчёты
7.1–7.6 и т.д.) живут внутри `output/` того же проекта, а не в отдельном
общем каталоге платформы — `project_id` всегда совпадает с именем папки в
`projects/`, поэтому все материалы проекта (входные, документы БА, артефакты
MCP) собраны в одном месте.
